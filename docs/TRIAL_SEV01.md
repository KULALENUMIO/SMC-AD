# 試行: SEV 01 を変換して、ポーズ・リギングして Unity へ（2026-11-13）

SEV 01（つなぎ用のブロックを持つロボットの素体）を使い、変換 → Blender（つなぎを外す・ポーズ・リギング）→ Unity の流れを一通り試した。
手は別パーツなので対象外。足首のめり込みは前提どおり、そのままにした。

成果物（`verify/sev01/` など）は、確認が済んだので削除した（2026-11-13）。

| ファイル | 内容 |
|---|---|
| `flow/sev01_posed_rig.blend` | ポーズとリグを付けた状態。Blender で開ける |
| `flow/sev01_rig.fbx` | Unity に入れた FBX |
| `flow/sev01_smcad.glb` | SM のマテリアルを渡すための SMC-AD 書き出し |
| `unity/unity_sheet.png` | Unity でレンダーした結果 |

## やったこと

| 工程 | 内容 | 結果 |
|---|---|---|
| 変換 | `-gltf -cullhidden -optimizeblocks -fixcoplanar -septype joints` | 57秒、26.7MB。ボディ17、ジョイント16（すべてベアリング）、155,544三角形、マテリアル20 |
| 構造の確認 | 色分けしてボディの位置を確認した | 胴（土台）→ 肩 → **小さなつなぎ** → 腕の付け根 → 腕。胴 → 腰 → 股関節 → 脚 → 足。胴の上に小さな板（Objects_3） |
| つなぎを外す | 肩と腕の付け根の間の小さなボディ（Objects_9 / Objects_17）を「ボディを外す」で外した | 腕の付け根の親が肩になった。位置のずれはなし |
| ポーズ | 腕の付け根を、自身の回転の中心で Y 軸まわりに ±82° 回し、腕を下ろした | 完成予想図とほぼ同じ立ち姿（`flow/blender_posed_*.png`） |
| リギング | スクリプトで、ボディごとに骨を1本作り（15本）、各ボディをその骨の子にした | 位置のずれはなし。肩の骨を回すと腕が付いてくる |
| Blender から書き出し | 標準の FBX 書き出し（骨＋メッシュ、頂点カラーはリニア） | 4.7MB |
| Unity | SMC-AD の .glb を取り込んで SM のマテリアルを作り、FBX のマテリアルを名前で SM のマテリアルに付け替えた（テストのスクリプトで） | 20/20 が SM Lit になった。頂点カラーあり。Generic のアバターが作られた。前は +Z を向いた。骨を回すと腕が動いた |

## 見つかった問題（今後の材料）

### 大きいもの
1. **SMC-AD の Unity 書き出しは、ポーズを運ばない**
   - .glb を Unity に入れると T ポーズのまま（つなぎを外したことだけは反映される）
   - 今回は、形・ポーズ・骨は FBX、見た目は SMC-AD の .glb、と二本立てにして、マテリアルの付け替えはテスト用のスクリプトで行った
   - → **FBX 書き出し**と、**Unity 側でマテリアルを自動で割り当てる仕組み**（取り込み時の後処理）が必要
2. **リグの自動生成がない**
   - 今回はスクリプトで作った（ボディ1つに骨1本、ジョイントの位置が骨の根元）
   - → 機能にする
3. **骨の向きがジョイントの軸と合っていない**
   - 骨の向きを「次のボディの方向」にしたため、Unity で骨を回す軸がジョイント（ベアリング）の回転軸とずれる
   - アニメーションを付けるときに、どの軸で回せばよいか分からない
   - → 骨のローカル軸を、ベアリングの回転軸に合わせて作る
4. **つなぎを外すと、そのつなぎが持っていた回転軸もなくなる**
   - 今回の青いつなぎは「腕を下ろす（前後軸まわり）」ベアリングの受けだった。外したので、腕を下ろすポーズは自由回転で付けた
   - 骨で動かすなら問題ないが、SMC-AD のジョイント情報（Unity の SMJoint の角度）では、このポーズを表せない
   - → 骨を使う運用に寄せる。または、外したつなぎの回転軸を子に引き継ぐ選択肢を付ける

### 中くらいのもの
5. **FBX ではパーツ番号（`_SM_SHAPE`）が消える**
   - Unity で Part Random のマスクや、パーツ単位の機能が効かなくなる
   - → 書き出し前に UV チャンネルへ焼き込む
6. **FBX のモデルには SMBlueprint / SMJoint が付かない**
   - ジョイントの情報と、書き出し結果のレポートが Unity に届かない（FBX の独自プロパティは辞書を運べない）
7. **名前が分かりにくい**
   - ボディの名前が `Objects_N` で、骨とメッシュが同じ名前になった（15組）
   - → 左腕・右脚などの名前を自動で付ける。骨とメッシュの名前を分ける
8. **描画が重い**
   - 15メッシュ × 平均約13マテリアルで、ドローコールが **203**。ゲームで1体動かすには重い
   - → マテリアルの統合（テクスチャ配列やアトラス）を検討する
9. **FBX の一番上に X −90° の回転が入る**
   - Blender → FBX の軸変換によるもの。前方は Unity の +Z で正しい

### 小さいもの・確認すること
10. **つなぎの判定が手作業**
    - 色分けして目で見て判定した
    - → 「小さくて、2つのベアリングに挟まれているボディ」を候補として表示すると楽になる
11. **胴の上の小さな板（Objects_3）は判断を保留した**
    - 子がなく、つなぎか頭の取り付け部の可能性がある。今回は残した
12. 変換は57秒かかった（大半は見えない面の削除）
13. 足首のめり込みは前提どおり、何もしていない

## うまくいったこと
- ボディを外す／戻す機能と、Unity 書き出しへの反映（つなぎ2つを除き、子を親につなぎ直した）
- FBX 経由のマテリアルの付け替え（名前で 20/20）と、頂点カラー（リニアのまま）
- Unity の Generic アバター、前方向（+Z）、骨で腕が動くこと

## その後の対応（2026-11-13）
- 1・6（ポーズを運ばない、SM の情報が届かない）→ FBX 書き出しと、Unity での自動設定を作った（CHANGELOG「Blender で調整・リギングしたものを、そのまま Unity へ」）
- 5（パーツ番号）→ FBX の UV チャンネルで運び、Unity で UV2 に移す
- 7（名前）→ ブループリント名＋番号にした
- 2・3（リグの自動生成、骨の軸）→ 方針により、扱わない（リギングは Blender で手作業。SMC-AD は手直しと受け渡しに集中する）
- つなぎ用のブロックが変換で消えることがある不具合（ブロックだけのボディ）を見つけて直した
