# 要件: シェーディングしやすいマテリアル構成と「材質タイプ」の分離

※ 名称はすべて仮。「SMC-AD」がコア、「SMC-AD+ ○○」が拡張機能のシリーズ名。

## 1. 目的と想定するユーザー
質感の付け方は、ユーザーのタイプによって2つの道を用意する。

| | 想定するユーザー | 担当 |
|---|---|---|
| A | ノードを自分で組める人。シェーディングで細かく作り込みたい | **SMC-AD（コア）**: 編集しやすい土台を用意する（ノードの配置の整理、チャンネルの取り出し口、マスク） |
| B | ノードはわからない。ボタンとスライダーだけで、気軽にそれっぽくしたい | **SMC-AD+ Surfaces（拡張）**: ノードを一切触らずに、材質を選んで調整できる |

- AとBは同じ土台の上で動く。Bで付けた材質を、Aの人があとからノードで作り込むこともできる（逆も可）
- 拡張は「SMC-AD+」シリーズの1つとして出す。今後、汚し・摩耗などの拡張も同じシリーズに追加できる形にする

## 2. 構成と責任範囲

| | SMC-AD（コア） | SMC-AD+ Surfaces（拡張・任意） |
|---|---|---|
| 役割 | 取り込み、SMシェーダの土台、ジョイント、色の差し替え、Unityへの書き出し | 材質タイプのプリセット、自動割り当て、ノード不要の調整UI |
| 依存関係 | 単体で完結する | コアに依存する（逆方向の依存は持たない） |
| 削除したとき | — | 既存のマテリアルはそのまま描画できる（ノードグループは .blend に残る） |
| Blender拡張ID（仮） | `smc_ad` | `smc_ad_plus_surfaces` |
| Unity | コアのパッケージ | 拡張で付けた値は、コアのシェーダのパラメータとして運ばれる（Unity側に拡張は不要） |

- 変換ツールは、材質の手がかり（`sm_surface`・physicsMaterial・metalProfile）をメタデータとして書き出し続ける。データ量はわずかで、拡張を使わない人にも「このパーツは金属」という情報として役立つ
- Unity側は、コアのシェーダが標準的なPBRの値（金属感・スムースネスなど）を受け取れるようにしておく。拡張で付けた値も、手作業で付けた値も、同じ入口を通る

## 3. コアのノード構成の要件

### N1. 最終シェーダは見える場所に置いた標準の Principled BSDF
- SMの処理をグループの中に閉じ込めず、マテリアル直下に標準の Principled BSDF を置く
- ユーザーはそのソケットに直接つないだり、間に Mix を挟んだりできる

### N2. SMのデコード部は1つのグループにまとめ、出力をPBRのチャンネルに分ける
グループ `SMC_Decode` の出力:

| 出力 | 内容 |
|---|---|
| Base Color | 塗装色とDifを合成した色 |
| Paint Mask | 1＝塗装部、0＝テクスチャ部（`SMC_Masks` と同じ意味） |
| Paint Color | 頂点の塗装色（そのまま） |
| Roughness | 1 − ASG.a |
| Specular | ASG.g（Principled の Specular IOR Level 用に換算済み） |
| Metallic | 0（SMの元の見た目。④で上書きする前提の差し込み口） |
| Emission Strength | ASG.b から計算した発光 |
| Normal | ノーマルマップ（Principled にそのままつなげるベクトル） |
| Alpha | 切り抜き用のアルファ（切り抜きのない材質は1） |

### N3. フレームで区切り、左から右へ固定の配置にする
```
[① SMテクスチャ] → [② 塗装・マスク] → [③ SMデコード] → [④ レイヤー（ここに追加）] → [⑤ 出力]
 Dif/Asg/Nor        塗装属性 / SMC_Masks   SMC_Decode       チャンネルごとの中継点          Principled BSDF
                    （色の差し替え）                                                    Material Output
```
- フレームには日本語のラベルと色を付ける。ノードの間隔と位置は、どのマテリアルでも同じにする
- テクスチャのノードは畳まずに表示し、「Dif／Asg／Nor」のラベルを付ける

### N4. レイヤーの差し込み口
- ③と⑤の間に、チャンネルごと（Base Color・Metallic・Roughness・Specular・Normal・Emission）の**中継点（Reroute）**を縦に並べる
- ユーザーは中継点の線上に Mix などを落とすだけで、層を追加できる
- Metallic は既定で 0（SMの元の見た目）。中継点に値をつなげば金属にできる

### N5. マスク用の補助グループ `SMC_Masks`
手作業のシェーディングで使う、以下のマスクを出力する。

| 出力 | 内容 |
|---|---|
| Paint Mask | 塗装部（1 − Dif.a） |
| Texture Mask | テクスチャ部（Dif.a） |
| Part Random | パーツごとのランダム値（`_SM_SHAPE` から作る） |
| Body Random | ボディごとのランダム値 |
| Up Facing | 上向きの面（ほこり・汚れ用） |
| Part ID | `_SM_SHAPE` の値そのもの |

- 縁や凹みのマスク（塗装はげ・汚れ用）は、汚し・摩耗の段階で追加する。Blender専用の Pointiness に頼るとUnityで再現できないので、変換ツール側で頂点に焼き込む案を基本とする

### N6. 色の差し替え（Override）は②のフレームに収める
- 既存の差し替え機能は②の中に置き、③以降の配置を崩さない

### N7. ユーザーが足したノードを壊さない
- SMC-ADが作るノードには、名前の先頭に `SMC.` を付けて区別する
- 「Rebuild SM Materials」では `SMC.` のノードだけを作り直す。ユーザーが追加したノードと、そのつながりは保つ
- 作り直しで中継点の位置が変わる場合も、中継点の名前（`SMC.Layer.Roughness` など）は変えない

### N8. ガラスも同じ考え方にする
- ガラスは Principled BSDF の Transmission を使う。または Glass BSDF をフレーム内で同じ並びに置き、同じ中継点を用意する

## 4. 拡張「SMC-AD+ Surfaces」の要件

### 基本方針: ノードを一切見せない
ユーザーはシェーダエディタを開かずに、サイドバーとビューポートだけで作業を完結できること。

### 機能
- S1. 材質タイプ（塗装金属・地金・ゴム・プラスチック・木・石・ガラス・標準）のプリセット（共有JSON）を持つ。既に実装した内容を移す
- S2. 材質タイプのノードは、コアの④の差し込み口に1つだけ置く（`SMC.Surface`）。中継点の間に挟まる形にし、外せば元に戻る
- S3. 取り込み時に、自動割り当て（変換ツールのメタデータ `sm_surface`）を使うかどうかを選べる。既定はオン
- S4. コアの更新で配置が変わっても動く。接続先は中継点の名前で探す

### ノードがわからない人向けの操作（UI要件）
- S5. **クリックで選ぶ**: ビューポートでパーツをクリックすると、そのパーツ全体が選ばれる（編集モードへの切り替えや、面の選択を意識させない）
- S6. **材質は見た目で選ぶ**: 材質のボタンを、プレビュー画像（球のサムネイル）付きで並べる。押すだけで割り当てる
- S7. **スライダーは日常の言葉で**: 「つや」「金属っぽさ」「ざらつき」「塗装の厚み（クリアコート）」「色味」など。専門用語（Roughness、Metallic など）は小さく併記する程度にする
- S8. **かんたんな質感の味付け**をプリセットに含める: 例として「新品の金属」「使い込んだ金属」「マットなゴム」「つやのあるプラスチック」。同じ材質タイプの中で、ワンクリックで切り替えられる
- S9. **安心して試せる**: どの変更もアンドゥできる。材質ごと・全体の「元に戻す」がある。変えた材質には印（●など）が付く
- S10. **影響範囲が分かる**: スライダーが「この材質の全パーツ」に効くのか、「このパーツだけ」なのかを常に表示する。このパーツだけ変えたい場合は「このパーツ用に複製」ボタンを使う
- S11. 自分で作った味付けを、名前を付けて保存し、他のブループリントでも使える（共有JSON。Unityにも持っていける）

## 5. Unityへの持ち込みの要件
- U1. Blenderから書き出すときは、以下の情報を受け渡す
  - Principled BSDF の値
  - 中継点に直接つながっている値（数値、色、`SMC_Masks` の単純な組み合わせ）
  - 色の差し替えの設定
  - 材質タイプの設定
- U2. **自由に組んだノードの網をそのまま移すことはできない**（Unityのシェーダはノードの構成が異なるため）。対応は次の段階に分ける
  - 段階1: 中継点の値が「定数」または「SMC_Masks × 定数のMix」の範囲なら、Unityのシェーダのパラメータに変換する
  - 段階2（将来）: それ以外の組み合わせはテクスチャに焼き込む。ただし、SMのUVはアトラスやタイル繰り返しなので、焼き込み用の別UVを作る必要がある
- U3. 書き出しのときに、移せなかったノードを一覧にして知らせる（黙って捨てない）

## 6. 未決事項（実装前に確認する）
- 中継点に「SMC_Masks × 定数のMix」以外のどこまでの組み合わせをUnityへ自動で変換するか（段階1として、定数・×定数・＋定数・マスクか定数で混ぜる Mix を実装した。ノードは1段まで）
- ガラスを Principled（Transmission）に統一するか、Glass BSDF を残すか
- 正式名称（コア: SMC-AD、拡張シリーズ: SMC-AD+ ○○ はいずれも仮）
- S8 の「味付け」プリセットの初期ラインナップ（仮で15種類を入れた。`surface_presets.json` の `flavors`）

## 7. 実装の順番（案）と進捗
1. ✅ コアのノード構成を作り直す（N1〜N8）。既存の材質タイプのコードは `addon_plus/smc_ad_plus_surfaces/` に退避した（2026-11-13）
2. ✅ SMC-AD+ Surfaces を別の拡張として作り、既存の材質タイプの機能を移す（S1〜S4）。`addon_plus/smc_ad_plus_surfaces/`（2026-11-13）
3. ✅ ノード不要のUIを作る（S5〜S11）。サイドバーの専用タブ「SMC-AD+」（2026-11-13）
4. ✅ Blender → Unity の書き出し（U1〜U3）と、Unity側のパラメータ対応（2026-11-13）。元の .glb に Blender の設定を足した `<名前>_smcad.glb` を書き出す。U2 は段階1（定数・レイヤー×定数・レイヤー＋定数・マスク／定数で混ぜる Mix）まで。段階2（焼き込み）は未着手
